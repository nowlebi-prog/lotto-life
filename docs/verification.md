# 구현과 검증 기록

검증일 2026년 11월 1일. 현재 게임은 브라우저의 메모리에서 진행되는 정적 앱입니다.

## 2026년 11월 2일 확률 개편

- 기존의 7개 사건 균등 배정은 4개가 1등 표여서, 회수 선택 기준 1등 표가 약 57% 등장했습니다.
- 시뮬레이션을 가중치 배정으로 변경했습니다. 1등 표는 기본·다수 당첨·분실·세탁기까지 합산 1.5%입니다. 보장 모드는 100%를 유지합니다.
- 4등·5등·일반 꽝을 추가하고 꽝에 세 가지 짧은 선택 결말을 넣었습니다. 일반 꽝과 회차 착각의 안내를 분리했습니다.
- 10,000개 등간격 난수 구간 검사에서 1등150개를 확인하는 결정적 테스트를 추가했습니다. 실제 플레이에서 발생하는 표본 변동과 구분합니다.
- 브라우저 캐시에 이전 게임 규칙이 남지 않도록 화면·모듈 주소에 1.1.0 버전을 지정했습니다.
- 수정 후 Node 테스트 15개, 모바일 분기 14개, 두 모드 전체 진행·PNG 저장·초기화 검사를 통과했습니다. 독립 코드 검토에서도 확률 합산과 소액 당첨·꽝 처리에 구체적인 잔여 문제를 발견하지 못했습니다.

## 실행한 검사

- Node 엔진 테스트 11개 통과. 두 성별의 20개 엔딩 연결, 1등 모드의 모든 대화 조합, 7개 랜덤 사건과 회수·실패, 일회 수령, 오래된 선택 무시, 표와 외형 불변, 회차와 보너스 판정, 금액 공개 시점을 검사했습니다.
- 전체 브라우저 흐름 통과. 두 모드 시작, 성별·닉네임, 1등 수령과 20개 선택, 선택한 외제차 엔딩, 실제 900×1200 PNG 내려받기, 새로고침 초기화, HTML처럼 보이는 닉네임의 일반 문자 표시를 확인했습니다.
- 모바일 랜덤 분기 9개 통과. 정상·다수 당첨·2등·3등·분실 회수/실패·회차 착각·세탁기 회수/실패가 각각 의도한 끝으로 이어졌습니다.
- 상호작용 회귀 4개 통과. 접근 가능한 모달 이름, 헤더 토글의 포커스 복원, 가족 축하 메시지 내용, 250ms 더블클릭의 단일 장면 전이를 확인했습니다.
- 320·390·768·1440px에서 시작·설정·이야기의 가로 넘침을 확인했고 문제가 없었습니다.
- 최종 `dist` 파일을 `/lotto-life/` 하위 주소에서 다시 전체 브라우저 검사했습니다. 상대 경로와 이미지 내려받기가 동작했습니다.
- 애플리케이션의 외부 네트워크 요청과 저장소 쓰기가 테스트 중 발생하지 않았습니다. 소스 검사에서도 진행 저장·분석·외부 런타임 의존성이 없음을 확인했습니다.
- 독립 코드 검토에서 Critical/Important 확정 문제가 없었고, 발견한 접근성·대화 표시 문제와 재현된 더블클릭 문제를 수정 후 재검증했습니다.

## 수정한 문제

호버 시 버튼을 위로 움직이는 표현이 마우스 가장자리에서 호버 진입과 이탈을 반복했습니다. 버튼 위치를 고정하고 색과 그림자만 바꾸도록 수정했습니다. 250ms 더블클릭이 두 장면을 넘기는 경우도 재현해 두 번째 클릭을 무시하도록 수정했습니다.

## 확인 범위와 한계

실제 Microsoft Edge의 Chromium 환경에서 자동 검사와 화면 확인을 했습니다. iOS Safari 실기기, 모든 보조기기, 실제 사람의 플레이 소요 시간은 별도로 측정하지 않았습니다. 5~10분은 대사 분량에 따른 목표 시간입니다. 모든 환경에서 오류가 전혀 없다고 보장하는 표현은 사용하지 않습니다.

F06 외형은 손이 잘리지 않도록 그림을 보정하면서 다른 프리셋보다 작게 표현되었습니다. 게임 동작에는 영향을 주지 않습니다. 다른 캐릭터와 동일한 애니메이션 세트를 새로 생성한 것은 아니며, 프리셋별 고정 포즈를 장면에 재사용합니다.

브라우저 보고서와 검수 스크린샷은 로컬 `.qa/`에 보존되며 공개 배포 파일에서는 제외합니다. 게임 자체는 이 검증 기록이나 플레이 기록을 서버로 보내지 않습니다.
